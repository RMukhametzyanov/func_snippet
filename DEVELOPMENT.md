# Руководство по разработке

## Настройка окружения разработки

### Требования

- **JDK 17** (обязательно, проект не поддерживает Java 25)
- **Gradle 8.5+** (загружается автоматически через wrapper)
- **PyCharm 2024.1+** или IntelliJ IDEA (для разработки)

### Настройка Java 17

Проект настроен на использование **Java 17**. Важно убедиться, что в системе установлена именно эта версия.

#### Проверка установленной версии Java

```powershell
java -version
```

Должно отображаться: `openjdk version "17.x.x"` или `java version "17.x.x"`

#### Настройка JAVA_HOME

**Важно:** Переменная окружения `JAVA_HOME` должна указывать на Java 17.

##### Вариант 1: Через PowerShell (от администратора)

```powershell
[System.Environment]::SetEnvironmentVariable("JAVA_HOME", "C:\Program Files\Eclipse Adoptium\jdk-17.0.18.8-hotspot", "Machine")
```

**Примечание:** Замените путь на актуальный путь к вашей установке Java 17.

##### Вариант 2: Через GUI

1. Откройте "Переменные среды" (Win + R → `sysdm.cpl` → "Дополнительно" → "Переменные среды")
2. В "Системные переменные" найдите `JAVA_HOME`
3. Измените значение на путь к Java 17 (например: `C:\Program Files\Eclipse Adoptium\jdk-17.0.18.8-hotspot`)
4. Перезапустите терминал/IDE

#### Настройка в проекте

Проект уже настроен на использование Java 17 через файл `gradle.properties`:

```properties
org.gradle.java.home=C\:\\Program Files\\Eclipse Adoptium\\jdk-17.0.18.8-hotspot
```

**Важно:** Если путь к Java 17 отличается, обновите этот файл.

### Сборка плагина

#### Локальная сборка

```powershell
.\gradlew.bat buildPlugin
```

Собранный плагин будет находиться в `build/distributions/json-test-viewer-2.0.0.zip`

#### Очистка и пересборка

```powershell
.\gradlew.bat clean buildPlugin
```

#### Проверка версии Gradle и Java

```powershell
.\gradlew.bat --version
```

Должно отображаться:
- **JVM**: `17.x.x (Eclipse Adoptium ...)` или `17.x.x (Oracle ...)`

#### Известные проблемы при сборке

**Ошибка:** `JAVA_HOME is set to an invalid directory: C:\Program Files\Java\jdk-25`

**Решение:** 
1. Убедитесь, что Java 25 удалена из системы
2. Установите `JAVA_HOME` на Java 17 (см. раздел "Настройка JAVA_HOME")
3. Проверьте путь в `gradle.properties`
4. Перезапустите терминал

**Ошибка:** `Could not find or load main class`

**Решение:** Проверьте, что `org.gradle.java.home` в `gradle.properties` указывает на правильный путь к Java 17.

### Запуск плагина в режиме отладки

```powershell
.\gradlew.bat runIde
```

Это откроет новое окно PyCharm с установленным плагином для тестирования.

## Архитектура плагина

### Основные компоненты

#### 1. FolderTreePanel.kt

Основной компонент панели с деревом файлов.

**Ответственность:**
- Отображение дерева файлов и папок
- Фильтрация папок `__pycache__`
- Управление split pane (дерево слева, структура справа)
- Обработка выбора файлов
- Открытие файлов по двойному клику

**Ключевые методы:**
- `setupPanel()` - настройка UI компонентов
- `refreshTree()` - обновление дерева файлов
- `buildTree(file: File)` - рекурсивное построение дерева

#### 2. FileStructurePanel.kt

Компонент для отображения структуры Python-файлов.

**Ответственность:**
- Парсинг Python-файлов
- Отображение структуры (классы, функции, методы)
- Всплывающие подсказки с мета-информацией

**Ключевые методы:**
- `showFileStructure(file: File)` - отображение структуры файла
- `parsePythonFileSimple(virtualFile: VirtualFile)` - парсинг Python-файла
- `parseParameters(paramsStr: String)` - парсинг параметров функции
- `extractDocstring(lines: List<String>, startIndex: Int)` - извлечение docstring
- `enrichParametersFromDocstring()` - обогащение параметров описаниями из docstring
- `buildTooltip(node: StructureNode)` - создание HTML tooltip

**Структуры данных:**
- `StructureNode` - узел дерева структуры с мета-информацией
- `ParameterInfo` - информация о параметре функции
- `StructureNodeType` - тип узла (FILE, CLASS, FUNCTION, METHOD)

#### 3. FolderScannerSettings.kt

Сервис для хранения настроек плагина.

**Ответственность:**
- Сохранение пути к папке для сканирования
- Загрузка настроек при старте

**Использует:**
- IntelliJ Platform `PersistentStateComponent` для сохранения настроек

#### 4. FolderScannerConfigurable.kt

UI компонент настроек плагина.

**Ответственность:**
- Отображение UI для выбора папки
- Валидация выбранной папки
- Сохранение настроек

#### 5. FolderTreeToolWindowFactory.kt

Фабрика для создания ToolWindow.

**Ответственность:**
- Создание и настройка ToolWindow
- Инициализация панели с деревом

## Парсинг Python-файлов

### Алгоритм парсинга

1. **Чтение файла**: Загружается содержимое файла через VirtualFile API
2. **Построчное чтение**: Файл читается построчно
3. **Определение уровня вложенности**: По количеству пробелов в начале строки
4. **Распознавание элементов**:
   - Классы: `^class\s+(\w+)(?:\([^)]*\))?\s*:`
   - Функции: `^def\s+(\w+)\s*\(([^)]*)\)\s*(->\s*([^:]+))?\s*:`
5. **Извлечение docstring**: Поиск многострочных строк в тройных кавычках
6. **Парсинг docstring**: Извлечение описаний параметров и возвращаемого значения

### Ограничения парсера

- Не поддерживает многострочные определения функций
- Не обрабатывает сложные типы в аннотациях (например, `List[str]`)
- Не парсит вложенные функции
- Простой парсинг docstring (только Google/NumPy style)

### Улучшения для будущих версий

- Использование Python PSI API для более точного парсинга
- Поддержка других форматов docstring (Sphinx, Epydoc)
- Поддержка многострочных определений функций
- Кэширование результатов парсинга

## Всплывающие подсказки

### Формат tooltip

Tooltip отображается в HTML формате с темной темой в стиле PyCharm:

- **Сигнатура функции**: Синий цвет (#569CD6)
- **Docstring**: Светло-серый (#D4D4D4)
- **Параметры**: 
  - Имя: Голубой (#9CDCFE)
  - Тип: Бирюзовый (#4EC9B0)
  - Значение по умолчанию: Оранжевый (#CE9178)
  - Описание: Зеленый (#6A9955)

### Обработка событий

Tooltip обновляется при движении мыши через `MouseMotionListener`:
- Определяется элемент под курсором
- Если это функция или метод, создается tooltip
- Tooltip устанавливается для компонента дерева

## Настройки плагина

### Хранение настроек

Настройки хранятся в файле `folder-scanner.xml` в директории конфигурации IntelliJ:
- Windows: `%APPDATA%\JetBrains\PyCharm<version>\options\`
- Linux: `~/.config/JetBrains/PyCharm<version>/options/`
- macOS: `~/Library/Application Support/JetBrains/PyCharm<version>/options/`

### Структура настроек

```xml
<application>
  <component name="FolderScannerSettings">
    <option name="folderPath" value="C:\path\to\folder" />
  </component>
</application>
```

## Тестирование

### Ручное тестирование

1. Запустите плагин в режиме отладки
2. Проверьте основные сценарии:
   - Выбор папки в настройках
   - Отображение дерева файлов
   - Фильтрация `__pycache__`
   - Выбор Python-файла
   - Отображение структуры
   - Всплывающие подсказки
   - Открытие файлов

### Тестовые данные

Создайте тестовую папку с Python-файлами, содержащими:
- Классы с методами
- Функции верхнего уровня
- Docstrings с описаниями параметров
- Типы параметров
- Возвращаемые значения

## Отладка

### Логирование

Для отладки используйте стандартный механизм логирования IntelliJ Platform:

```kotlin
import com.intellij.openapi.diagnostic.Logger

private val LOG = Logger.getInstance(FileStructurePanel::class.java)

LOG.debug("Parsing file: ${file.name}")
```

Логи можно просмотреть в `Help → Show Log in Explorer` или `Help → Show Log in Finder`.

### Точки останова

Установите точки останова в:
- `parsePythonFileSimple()` - для отладки парсинга
- `buildTooltip()` - для отладки tooltip
- `refreshTree()` - для отладки обновления дерева

## Известные проблемы

1. **Многострочные определения функций**: Не поддерживаются
2. **Сложные типы**: Парсер может некорректно обработать сложные типы в аннотациях
3. **Производительность**: При большом количестве файлов парсинг может быть медленным
